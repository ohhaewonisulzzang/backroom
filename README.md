# Backrooms Level 0 — 2D 탑뷰 멀티플레이 공포 게임

Next.js(화면) + Socket.io(실시간 서버)로 만든 프로토타입입니다.

## 실행

```bash
npm install
npm run dev          # 개발 모드  → http://localhost:3000
npm run build        # 배포용 빌드
npm start            # 배포 모드 실행 (build 후)
npm test             # 퍼즐 생성기 검사 + 멀티플레이 서버 자동 테스트
```

친구와 하려면 같은 **방 이름**을 입력하면 됩니다 (방당 최대 4명).
`http://주소:3000/?room=우리방` 처럼 링크로 공유해도 됩니다.

## 메인 메뉴 / 멀티플레이

- 첫 화면: 형광등 켜진 Level 0 을 천천히 떠도는 배경, 왼쪽에 **설정 · 플레이 · 조작법 · 괴물 도감 · 크레딧**. 가끔 괴물 얼굴이 튀어나온다 (설정에서 끌 수 있음).
- **플레이 → 혼자 플레이**: 바로 시작.
- **플레이 → 멀티 플레이**: 이름 + 방 코드를 넣고 **참가하기**, 또는 **방 만들기** → 이름 입력 → **만들기**.
- **대기방**: 4자리 방 코드(복사 버튼), 들어온 사람 목록(최대 4명), 방호복 색 선택(기본 · 초록 · 파랑 · 빨강, 겹치지 않음).
  방장만 **게임 시작**을 누를 수 있고, 방장이 나가면 다음 사람에게 넘어간다.
- 방랑자와 스킨 스틸러의 방호복 색은 랜덤이다 (스킨 스틸러가 동료처럼 보일 수 있다).

## 게임 방법

- **오프닝:** 처음 Level 0 에 들어가면 캠코더 녹화 화면으로 이야기가 나온다. 친구들과 폐건물 탐험 영상을 찍다가 벽이 노랗게 변하고, 바닥이 꺼지며 **노클립**으로 백룸에 떨어진다 (신호가 끊기면 바로 Level 0. 내레이션 없음).
  멀티에서는 실제 동료들이 같이 촬영하던 친구들로 나오고 모두 같이 떨어진다. 혼자 하면 NPC 친구 둘이 남고 나만 떨어진다. `ENTER`/`ESC`/`SPACE` 로 건너뛸 수 있다.
- **목표:** 레벨마다 미션(열쇠 모으기 / 부품 배달 / 장치 작동 / 시간 버티기)을 끝내면 출구(철문, EXIT 표시)가 열린다. 그 문으로 나가면 탈출.
- **퍼즐 단말기 (Level 1 부터):** 열쇠 몇 개는 낡은 CRT 단말기 안에 잠겨 있다. 앞에서 `E` 를 누르면 퍼즐이 열리고, 풀면 열쇠를 얻는다.
  푸는 동안에도 게임은 계속 진행된다. 기억력 퍼즐을 **틀리면 경보가 울려** 소리에 민감한 엔티티가 몰려온다.
  | 퍼즐 | 내용 |
  |---|---|
  | 한붓 그리기 | 모든 선을 한 번씩만 지나도록 점을 한 번에 잇는다 (뒤로 가면 취소) |
  | 기억력 | 깜빡인 순서대로 번호 패드를 누른다 (순서 3~5개, 패드 4~6개) |

  레벨이 올라갈수록 조금씩 어려워진다. (전등 끄기·숫자 퀴즈·슬라이드 퍼즐도 코드에는 남아 있어서 `puzzles` 에 이름만 넣으면 다시 쓸 수 있다.) 레벨별 퍼즐 종류는 `shared/config.js` 의 `LEVELS[].puzzles` 에서 바꿀 수 있다.
  판정은 서버가 한다 (`shared/puzzles.js`. 서버와 클라이언트가 같은 seed 로 같은 퍼즐을 만든다).
- **정신력:** 시간이 지나면 줄어들고, 어두운 곳에서는 더 빨리 준다 (손전등을 켜면 조금 덜 준다. 사물함 안에서는 천천히 준다). **아몬드 워터**로 회복한다.
  45 아래로 내려가면 **스마일러 환각**이 보인다. 주변에 가짜 스마일러가 잔뜩 나타나 다가오고, 화면이 보랏빛으로 일렁이며 속삭임이 들린다.
  0 이 되면 **플레이어가 터져서** 죽는다.
- **사망 연출:** 엔티티마다 다르다. 하울러는 할퀴고, 하운드는 물어뜯는다. 스마일러는 미소로 꽉 물고, 스킨 스틸러는 찢어진 입으로 삼킨다.
  파티고어는 피 색종이를 뿌리고, 데스모스는 나방 떼로 덮는다. 광인은 살점 촉수로 감싸고, 스크래처는 마구 할퀸다. 정신력이 바닥나면 터진다.
  죽은 자리에는 핏자국이 남는다. 연출은 모두 픽셀아트로 그린다.
  **설정**에서 "사망 점프스케어"(괴물이 덮쳐 오는 화면)와 "잔인한 연출"(피·살점·핏자국)을 각각 끌 수 있다.
- **조작:** `WASD`/방향키 이동, 마우스 조준, `SHIFT` 달리기(스태미나), `F` 손전등, `C` 웅크리기(느리지만 발소리 없음), `E` 사물함·탁자 숨기/나오기, `1`~`4` 아이템 사용, `,` 감정 표현(말풍선 + 목소리, 소리에 민감한 엔티티가 듣는다), `SPACE` 관전 대상 전환(사망/탈출 후), `ESC` 메뉴(계속하기 · 설정 · 조작법 · 메인 메뉴로). 혼자 하기에서는 ESC 로 실제로 일시정지되고, 멀티에서는 게임이 계속 진행된다
- **조명:** Level 0 은 천장 형광등 덕분에 대부분 밝다. 형광등이 나간 **어두운 구역**이 몇 군데 있고, 일부 등은 깜빡인다.
  벽 뒤처럼 시야가 가려진 곳은 흐리게 보이며, 그곳에 있는 엔티티는 보이지 않는다.
- **사물함:** 벽에 붙은 철제 사물함 앞에서 `E` 를 누르면 숨는다. 숨어 있는 동안은 엔티티 눈에 보이지 않는다.
  단, **쫓기던 중에 숨는 장면을 들키면**(시야가 끊긴 지 1.5초 안에 도착하면) 끌려 나온다. 쫓기기 전에 숨어야 안전하다.
- **공격 = 즉사.** 모든 엔티티는 청각이 없고 **눈으로만** 플레이어를 찾는다. 달려도 소리로 들키지는 않는다.

### 테스트 모드

개발 서버(`npm run dev`)에서는 게임 중 **`` ` `` 키**(숫자 1 왼쪽)를 누르면 테스트 패널이 열린다.
다음 레벨 / 레벨 선택, 열쇠 획득·출구 개방, 열쇠·퍼즐 단말기·출구로 순간이동, 아이템 소환, 정신력 -30, 엔티티 소환·전체 제거,
무적, 부활, 밝게(어둠·안개 끄기), 미니맵 전체 공개를 할 수 있다.
명령은 서버가 검사하므로 배포 서버(`npm start`)에서는 꺼져 있다. 배포 서버에서도 켜려면 `BACKROOMS_TEST=1` 환경변수를 준다.

### 연출

- 레벨 시작: 레터박스 + 레벨 제목, 카메라가 멀리서 내려온다 (그동안 엔티티도 대기)
- 하울러가 깨어날 때: 붉은 맥박 + 흔들림
- 탈출할 때: 화면이 찢어지며 하얗게 노클립
- **LEVEL END 를 탈출하면 엔딩**: 노클립 섬광 → 밤거리, 마지막에 게임 이름 **BACKROOMS** 만 떠오른 뒤 끝난다 (내레이션 없음). 멀티는 엔딩 후 대기방으로 돌아간다

### 채팅 · 보이스 챗 · 키 설정

- **채팅:** `ENTER` 로 입력창을 열고 `ENTER` 로 보낸다 (`ESC` 취소). 대기방에서도 된다. 머리 위에 말풍선도 뜬다. 죽은 사람의 채팅엔 `(관전)` 이 붙는다.
- **보이스 챗:** 설정 → 보이스 챗에서 켠다. 마이크 장치 선택, 마이크 볼륨, **마이크 감도**(이 선을 넘는 소리만 보냄, 레벨 막대로 확인), 들리는 목소리 볼륨, **루프백 테스트**(내 목소리 듣기), 마이크 켜기/끄기(게임 중 `M`).
  - 거리에 따라 볼륨이 달라진다: 2.5칸 안은 그대로, 멀어질수록 작고 먹먹해져 약 25칸 넘으면 안 들린다. 벽 너머는 절반, 사물함 속은 먹먹하게. 좌우 방향도 들린다.
  - 죽은 사람은 모두의 목소리를 듣지만, 산 사람에게 죽은 사람 목소리는 들리지 않는다. 대기방에선 모두 같은 크기.
  - 말하는 소리는 감정 표현처럼 **귀 밝은 엔티티**(파티고어·광인·스크래처)가 듣는다.
  - WebRTC(브라우저끼리 직접 연결, 서버는 연결 정보만 중계) — 공용 STUN 서버만 써서, 일부 회사/학교 네트워크에선 연결이 안 될 수 있다 (TURN 서버 필요). 마이크는 `https` 또는 `localhost` 에서만 열린다.
- **키 설정:** 설정 → 키 설정에서 모든 동작의 키를 바꿀 수 있다 (브라우저에 저장). 이미 쓰는 키를 고르면 서로 바뀐다.
- **영상 건너뛰기:** 오프닝/엔딩은 `SPACE` 를 1초 동안 꾹 누르면 건너뛴다.

**미션 종류** (레벨 시작 화면과 왼쪽 위에 표시):
- **열쇠** — 열쇠를 다 모으면 출구가 열린다. 일부(또는 전부)는 퍼즐 단말기 안에 있다.
- **배달** — 흩어진 부품을 주워(한 사람당 2개까지) 시작 지점 근처 장치에 가져다 놓는다. 죽으면 들고 있던 부품이 그 자리에 떨어진다.
- **작동** — 벽의 밸브(또는 발전기)에서 `E` 를 누르면 핸들 창이 열린다. 마우스(손가락)로 잡고 시계 방향으로 몇 바퀴 돌린다. 돌리는 소리를 소리에 민감한 엔티티가 듣고 온다.
- **생존** — 정해진 시간 동안 살아남으면 출구가 열린다. 시간이 갈수록 엔티티가 빨라진다. 모두 숨어만 있으면 시간이 멈춘다.

미션이 진행될수록 엔티티의 추격 속도가 최대 25% 빨라진다. 맵은 81×81 타일.

|---|---|---|---|
| 방랑자 | 바랜 방호복을 입은 사람 | 길을 잃고 천천히 배회한다. **무해** | 무시해도 된다. 단, 스킨 스틸러일 수도 있다 |
| 하울러 | 철사 뭉치 같은 몸 | 라운드 시작 40초 뒤 깨어난다. 보이면 비명을 지르고 추격하며, 걷기보다 빠르다. 멀리 떨어지면 근처로 순간이동한다 | 달려서 시야를 끊는다. 모퉁이를 활용 |
| 스마일러 | 어둠 속의 하얀 미소 | 어두운 구역 안에서만 움직이고, 어둠 속에 있는 플레이어만 노린다 | 손전등을 비추면 사라진다. 밝은 곳으로 나가도 된다 |
| 스킨 스틸러 | 방랑자로 위장 → 몸까지 찢어진 입 | 다가와서 "hello?" 하고 말을 건 뒤 정체를 드러내고 추격한다 | 말을 걸면 즉시 도망. 방독면 유리가 살짝 붉으면 가짜다 |
| 파티고어 | 노란 몸, 문어 빨판 손, 붉은 풍선, 삐뚤게 그린 웃는 얼굴 | 제자리에서 시선을 좌우로 돌리며 감시한다(바닥에 시야가 보임). 보이면 추격, **발소리**가 들리면 확인하러 온다 | 시야 사각지대로 이동하고, 가까이선 `C` 로 웅크려 소리를 죽인다. 탁자 밑에 숨기 |
| 데스모스 | 거대한 나방 (붉은 겹눈, 눈알 무늬 날개) | 벽에 붙어 있다가 **발소리**나 **손전등 빛**에 날아온다. 목소리엔 반응 없음 | 웅크려 걷고 손전등을 끈다. 살충제로 쫓아낸다 |
| 광인 | 붉은 살점으로 뒤덮인 인간형 | 앞을 못 본다. 발소리·목소리 쪽으로 다가온다. 플레이어보다 느림 | 소리를 내지 않는다. 조명탄으로 유인 |
| 스크래처 | 심하게 마른 긴 팔다리, 붉은 안광 | 네발로 기어다니며 소리로만 찾는다. 귀가 아주 밝다 | 책상 밑에 숨는다. 웅크려 이동 |
| 하운드 | 사람 머리를 한 개 | 보이면 네 발로 추격한다 | 손전등을 비추면 겁먹고 물러난다 (너무 가까우면 소용없음) |

## 폴더 구조

```
server.mjs              ← 서버 시작점: Next.js + Socket.io 를 한 프로세스/한 포트로 실행
server/
  socket.js             ← 접속, 방 입장/퇴장 처리
  GameRoom.js           ← 방 하나의 "게임 진행자" (괴물 AI, 열쇠, 사망, 라운드)
shared/                 ← 서버와 브라우저가 "똑같이" 쓰는 코드
  config.js             ← 속도, 시야, 괴물 능력치 등 숫자
  map.js                ← seed 로 미로 생성
  physics.js            ← 벽 충돌, 레이캐스팅(시야)
  monster.js, player.js ← 괴물 AI / 플레이어 데이터
game/client/            ← 브라우저 게임 엔진
  sprites.js            ← 픽셀아트 캐릭터/엔티티 (문자열 도트 → 캔버스)
  texture.js            ← 16x16 픽셀 타일 (벽지, 카펫, 3/4 시점 벽)
  lighting.js           ← 형광등 라이트맵, 깜빡임, 손전등, 시야 안개
  engine.js             ← 게임 루프 + 서버 메시지 처리
app/, components/       ← Next.js 페이지와 React UI (타이틀, 결과 화면)
```

## 실시간 멀티플레이는 어떻게 돌아가나? (쉬운 설명)

### 한 줄 요약

> **서버가 "게임 진행자(심판)"이고, 브라우저는 "화면"입니다.**
> 둘은 Socket.io 라는 **계속 열려 있는 전화선**으로 1초에 20번씩 대화합니다.

### 1. 전화선 — Socket.io

보통 웹사이트는 "편지" 방식입니다. 브라우저가 요청을 보내면 서버가 답장하고 연결이 끊깁니다.
게임은 이 방식으로는 느립니다. 그래서 **WebSocket**이라는 **끊지 않는 전화선**을 엽니다.
Socket.io 는 이 전화선을 쉽게 쓰게 해주는 도구입니다. 연결이 불안정하면 다른 방식으로 자동으로 우회합니다.

### 2. 누가 무엇을 결정하나

| 결정하는 것 | 누가 | 이유 |
|---|---|---|
| **내 캐릭터 이동** | 내 브라우저 → 서버가 검사 | 키를 누르자마자 움직여야 답답하지 않음 |
| 괴물 위치 / AI | **서버** | 모두가 같은 괴물을 봐야 함 |
| 잡혔는지(사망) | **서버** | 판정이 사람마다 다르면 안 됨 |
| 열쇠 획득 / 출구 열림 / 탈출 | **서버** | 같은 열쇠를 두 명이 줍는 일 방지 |
| 미로 모양 | 서버는 **seed 숫자 하나만** 보냄 | 같은 숫자 → 같은 미로. 맵 전체를 보낼 필요 없음 |

이렇게 서버가 최종 결정권을 갖는 구조를 **"서버 권위(Server Authoritative)"** 방식이라고 합니다.
누가 브라우저 코드를 조작해 벽을 통과하거나 순간이동해도, 서버가 **"그건 안 돼"** 하며 원래 위치로 되돌립니다(`correct` 메시지).

### 3. 1초 동안 일어나는 일

```
내 브라우저                         서버 (GameRoom)                     친구 브라우저
-----------                         ---------------                     -------------
키 입력 → 즉시 내 화면에서 이동
내 위치 전송 ──(20번/초)──▶  위치 검사 (너무 빠른가? 벽 속인가?)
                            괴물 AI 계산 (30번/초)
                            잡혔나? 열쇠 주웠나?
           ◀──(20번/초)── "스냅샷": 모든 플레이어 + 괴물 위치 ──▶  받은 위치로 부드럽게 이동
```

### 4. "원활한가?" — 네, 이 규모에서는 충분합니다

- **보내는 양이 아주 작습니다.** 실제로 측정해 보니 스냅샷 하나가 약 **615바이트**였습니다 (괴물 5마리, 플레이어 1명 기준).
  1초에 20번이면 약 **12KB/s**로, 유튜브 영상의 1%도 안 되는 양입니다.
- **내 캐릭터는 지연이 0입니다.** 서버 응답을 기다리지 않고 내 화면에서 먼저 움직입니다(클라이언트 예측).
- **다른 사람과 괴물은 "보간"으로 부드럽게 보입니다.** 1초에 20번 오는 위치 사이를 자연스럽게 이어서 그립니다.
  그래서 뚝뚝 끊기지 않습니다.
- **느껴지는 지연:** 다른 플레이어와 괴물은 실제보다 약 **50~150ms 늦게** 보입니다 (인터넷 거리에 따라 다름).
  협동 공포 게임에서는 거의 느껴지지 않는 수준입니다. 1ms 를 다투는 FPS 게임과는 다릅니다.

### 5. 꼭 알아야 할 주의점

**① Vercel 에는 그대로 배포할 수 없습니다.**
Next.js 를 보통 올리는 Vercel 은 "요청이 올 때만 잠깐 켜졌다 꺼지는" 서버리스 방식입니다.
그래서 **계속 열려 있어야 하는 전화선(WebSocket)과 계속 돌아야 하는 괴물 AI를 유지할 수 없습니다.**
이 프로젝트는 `server.mjs` 가 **계속 켜져 있어야** 합니다. 그래서 아래 같은 곳에 배포해야 합니다.

- Railway, Render, Fly.io, AWS EC2/Lightsail, 일반 VPS, Docker
- 명령어: `npm install && npm run build && npm start`

(나중에 꼭 Vercel 을 쓰고 싶다면, 화면(Next.js)만 Vercel 에 올리고 게임 서버(`server/`)는 따로 띄우는 구조로 나누면 됩니다.)

**② 방 정보는 서버 메모리에 있습니다.**
서버를 재시작하면 진행 중인 게임이 사라집니다. 게임 한 판이 몇 분짜리라서 프로토타입에서는 문제없습니다.

**③ 서버 1대 기준입니다.**
서버 1대로 동시 접속 수백 명(방 수십~백 개)까지는 무난할 것으로 예상합니다. 다만 아직 부하 테스트는 하지 않았습니다.
그 이상 늘리려면 Socket.io Redis 어댑터와 방별 서버 고정(sticky session)이 필요합니다. 지금 단계에서는 필요 없습니다.

**④ 이동 검사는 기본 수준입니다.**
속도 초과와 벽 안 좌표만 막습니다. "벽을 살짝 스치며 통과" 같은 정교한 치트까지 막으려면 이동 계산 자체를 서버로 옮겨야 합니다.

## 메시지 목록 (개발자용)

| 방향 | 이벤트 | 내용 |
|---|---|---|
| 브라우저 → 서버 | `join` | `{ name, room }` |
| 브라우저 → 서버 | `state` | `{ x, y, angle, flashlight, sprinting }` (20Hz) |
| 서버 → 브라우저 | `init` | 내 id, seed, 플레이어/괴물/열쇠 상태 (입장 시) |
| 서버 → 브라우저 | `round` | 새 라운드 시작 (새 seed) |
| 서버 → 브라우저 | `snapshot` | 모든 플레이어 + 괴물 위치 (20Hz) |
| 서버 → 브라우저 | `playerJoined` / `playerLeft` | 입장 / 퇴장 |
| 서버 → 브라우저 | `keyCollected` | 열쇠 번호, 주운 사람, 개수, 출구 열림 여부 |
| 서버 → 브라우저 | `objective` | 열쇠가 아닌 미션 진행 (부품 줍기/배달/떨어뜨림, 장치 완료, 생존 끝) + 미션 상태, 출구 열림 여부 |
| 서버 → 브라우저 | `playerDied` / `playerEscaped` | 사망(죽인 괴물 종류) / 탈출 |
| 서버 → 브라우저 | `monsterAlert` | 괴물이 누군가를 발견함 |
| 서버 → 브라우저 | `roundEnd` | 결과 + 다음 라운드까지 남은 초 |
| 서버 → 브라우저 | `correct` | 잘못된 이동 → 서버 위치로 되돌림 |
| 서버 → 브라우저 | `joinError` | 방이 가득 참 |
