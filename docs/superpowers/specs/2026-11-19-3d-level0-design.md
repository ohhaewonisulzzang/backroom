# 3D Level 0 — 설계 문서

- 날짜: 2026-11-19
- 브랜치: `3d` (main `4a1cfa0` 에서 갈라짐)
- 상태: 승인됨 (2026-11-19)

## 1. 왜 하는가

지금 게임은 위에서 내려다보는 2D 픽셀 게임이다. 사용자는 이것을 "진짜 백룸 게임처럼" 1인칭 3D 로 만들고 싶어 한다.
참고로 든 것은 친구들끼리 하는 1인칭 백룸 협동 게임 영상(유튜브 "김블루 백룸 스피드런")이다. 분위기와 장르만 참고하고, 특정 게임의 맵·괴물 디자인은 가져오지 않는다. 맵·괴물은 지금처럼 백룸 위키 설정으로 우리 것을 만든다.

사용자가 가져오고 싶다고 한 것 (스피드런 요소는 제외):

1. **진짜 같은 복도와 조명**: 누런 벽지, 축축한 카펫, 웅웅거리며 깜빡이는 형광등
2. **친구들끼리 떠들면서 길을 찾는 재미**: 멀티플레이와 보이스챗
3. **괴물에게 쫓길 때의 공포**

사용자는 "Unity 같은 엔진이 제일 좋긴 한데 일단 three.js 로 먼저"라고 했다. 그래서 이번 작업은 브라우저 3D 로 느낌을 잡아 보는 첫 단계다. 나중에 엔진으로 옮길 수도 있으니, 게임 판정이 화면과 따로 있는 지금 구조(서버 권위)를 깨지 않는다.

## 2. 목표 / 하지 않을 것 / 실패로 보는 것

**목표**
- Level 0(THE LOBBY)을 1인칭 3D 로 플레이할 수 있다. 혼자 하기와 멀티 모두.
- 마우스로 둘러보고(포인터 잠금), WASD 로 움직이고, 기존 키(달리기·웅크리기·손전등·E·아이템·감정 표현)가 그대로 동작한다.
- 형광등 조명, 깜빡임, 손전등, 어둠, 안개가 실감 난다.
- 하울러가 어둠 속에서 다가오는 게 보이고, 그 방향에서 소리가 들린다. 잡히면 지금 있는 사망 연출과 점프스케어가 나온다.
- 친구는 3D 사람 모습으로 보이고, 친구 목소리와 손전등도 그 방향에서 보이고 들린다.
- 2D 클라이언트와 3D 클라이언트가 같은 방에서 같이 놀 수 있다. 서버 프로토콜은 바꾸지 않는다.

**하지 않을 것 (이번 단계)**
- Level 0 밖의 레벨을 3D 로 만들기. 다른 레벨은 지금 2D 화면으로 그대로 플레이한다.
- 외부 3D 모델·텍스처 파일 쓰기. 텍스처와 모델은 코드로 만든다(절차적 생성).
- 서버 게임 규칙 바꾸기 (`server/`, `shared/` 의 판정·AI·맵 생성).
- 메인 메뉴·대기방·엔딩·오프닝을 3D 로 바꾸기. 지금 화면을 그대로 쓴다.
- 스피드런 요소.
- Unity·Unreal 같은 엔진으로 옮기기.

**실패로 보는 것 (돌아가더라도)**
- 평범한 노트북(내장 그래픽)의 "낮음" 품질에서 30fps 를 못 넘긴다.
- 3D 를 켜면 멀티가 깨진다. 2D 친구와 같이 못 놀거나, 위치·사망·열쇠가 어긋난다.
- 화면이 깔끔한 게임처럼 보이고 무섭지 않다. 백룸 특유의 낡고 누런 느낌과 형광등 소음이 없다.
- 기존 `npm test` 가 깨진다.

## 3. 제약

- Next.js 15 + React 19 + socket.io 커스텀 서버(`server.mjs`)를 그대로 쓴다. 서버는 한 포트에서 같이 돈다.
- 의존성은 `three` 하나만 추가한다. 정확한 버전을 고정한다(예: `three@0.170.0`). 후처리(EffectComposer 등)는 `three/examples/jsm` 에서 가져온다.
- 서버 좌표는 px 단위이고 타일 하나는 48px(`TS`)이다. 서버는 이동 거리와 벽 통과를 검사하므로 클라이언트가 보내는 x, y 는 지금과 같은 px 좌표여야 한다.
- 플레이어가 바라보는 방향 `p.angle`(라디안, 2D 화면 기준 atan2(dy, dx))은 서버가 손전등 판정(`litBy`) 등에 쓴다. 3D 의 좌우 방향(yaw)이 곧 `p.angle` 이어야 한다.
- 태블릿은 지금 지원한다(`DeviceGate` 가 휴대폰은 `MobileGuide` 안내 화면으로 보내고, 태블릿만 게임에 들어간다. 터치 스틱). 3D 에서도 태블릿 터치로 플레이할 수 있어야 한다. 휴대폰 지원은 이번 범위 밖이다.
- 코드 주석·UI 문자열은 지금처럼 한국어로 쓰고, 화면에 나오는 새 문자열은 `shared/lang/*` 에 영어 번역을 넣는다.

## 4. 방법 (검토한 것들)

| 방법 | 장점 | 단점 | 결정 |
|---|---|---|---|
| **A. three.js 로 게임 화면만 새로 그리기** | 서버·맵·AI·멀티·UI 를 그대로 씀. 브라우저에서 바로 돌아감 | 조명·그림자를 세게 쓰면 저사양 기기가 버벅임 → 품질 설정 필요 | **선택** |
| B. 둠식 레이캐스터 (캔버스) | 가볍고 어디서나 돎 | 위아래로 못 보고 조명이 단순해 "진짜 같은 복도"와 거리가 멂 | 제외 |
| C. Unity 등 게임 엔진 | 그래픽 최고 | JS 서버 판정·맵 생성·멀티를 다시 짜야 함. 사실상 게임을 새로 만드는 것 | 지금은 제외 (사용자: "일단 three.js 먼저") |

괴물 표현은 둘 중 **간단한 절차적 3D 모델**을 쓴다. 다른 안은 기존 픽셀 그림을 판자처럼 세우는 빌보드였는데, 사실적인 복도에 도트 괴물이 서 있으면 어색해서 뺐다. 어둠과 안개 속에서 실루엣과 빛나는 눈만 보이게 하는 게 더 무섭고 만들기도 싸다.

## 5. 설계

### 5.1 전체 구조

```
React (BackroomsGame.jsx) ── 메뉴/대기방/설정 UI (그대로)
        │
engine.js (Game 상태, 서버 이벤트, 입력) ── 대부분 그대로
        │  phase === 'game' 일 때
        ├── 지금 레벨이 Level 0 이고 설정 '3D 화면' 이 켜져 있으면 → Renderer3D (새로 만듦)
        └── 그 밖 → 기존 Renderer (2D)
```

- 새 폴더 `game/client/three/` 에 3D 코드를 모은다. 파일은 대략 다음과 같다.
  - `renderer3d.js`: Renderer3D 클래스. 기존 Renderer 와 같은 모양(`setLevel(level)`, `render(game, dt)`, `resize()`)이라 엔진이 갈아 끼울 수 있다.
  - `world.js`: 맵을 3D 메시로 짓기
  - `materials.js`: 절차적 텍스처
  - `actors.js`: 괴물·플레이어·아이템 모델
  - `lights.js`: 조명·깜빡임
  - `post.js`: 후처리
- 화면은 캔버스 두 장을 겹친다.
  - 아래 `<canvas>`: three.js WebGL
  - 위 `<canvas>`: 2D 오버레이. 기존 HUD(`hud.draw`), 사망 연출(`drawDeathOverlay`), 점프스케어(`drawGameScare`, `drawJumpscare`), 사물함 안 시점(`drawLockerView`), 시네마틱 등 화면 고정 2D 그림을 재사용한다.
  - 월드 위에 뜨는 것(E 안내, 이름표, 말풍선)은 3D 좌표를 화면 좌표로 투영해서 오버레이에 그린다.
- 2D Renderer 는 지우지 않는다. 엔진이 레벨이 바뀔 때(`loadRound`) 어느 쪽을 쓸지 고른다. 메뉴 배경(`renderMenu`)과 엔딩(`renderEnding`)은 계속 2D Renderer 가 그린다.

### 5.2 좌표와 크기

- 3D 단위는 1 = 1m. 변환 상수: `PX_PER_M = 32`. 그러면 타일 48px = 1.5m 다. **사용자 결정 (2026-11-19)**:
  - 서버가 이동 속도(px/s)를 검사하므로 속도는 못 바꾼다. 그래서 세상 크기로 체감 속도를 맞춘다.
  - 20px/m(타일 2.4m)이면 걷기가 초속 6.9m 로 날아다니는 느낌이라 공포와 맞지 않는다.
  - 32px/m 에서는 걷기 138 → 4.3m/s(빠른 걸음), 달리기 222 → 6.9m/s, 웅크리기 72 → 2.3m/s, 하울러 추격 198 → 6.2m/s 다.
  - 좁고 천장 높은 복도가 되고, 이것도 백룸 느낌이다.
- 천장 높이 2.7m, 눈높이: 서 있을 때 1.6m, 웅크리면 1.0m. 바뀔 때 부드럽게 이어진다. 시야각(FOV)은 좁은 복도에서 답답하지 않게 75° 안팎으로 하고, 만드는 사람이 정한다.
- 2D (x, y) → 3D (x / 32, 높이, y / 32). 2D 의 y 축이 3D 의 z 축이다. 이 상수는 한 곳(`game/client/three/units.js`)에만 둔다.
- 카메라 yaw 는 `p.angle` 과 같은 값으로 쓴다(atan2 기준을 맞추는 변환은 한 곳에서 처리한다). pitch(위아래)는 클라이언트에만 있고 ±80° 로 제한한다.

### 5.3 조작 (1인칭)

- **PC**: 게임 캔버스를 클릭하면 포인터 잠금. 마우스 움직임 → yaw/pitch, 감도 설정이 있다. ESC 는 지금처럼 메뉴를 연다(포인터 잠금도 풀림).
  - 지금 "마우스 왼쪽 = 아이템 사용"은 포인터 잠금 중의 왼쪽 클릭으로 그대로 쓴다.
- **이동**: `updateLocalPlayer` 에 `opts.firstPerson` 을 추가한다. 켜져 있으면 입력 벡터(W=앞, S=뒤, A/D=옆걸음)를 yaw 기준으로 돌리고, 각도는 마우스 커서 위치 대신 마우스 이동량으로 바꾼다. 속도·스태미나·충돌(`moveEntity`)·서버 전송은 그대로라서 서버가 보기엔 차이가 없다.
- **터치**: 왼쪽 스틱 = 이동(yaw 기준), 오른쪽 스틱 = 둘러보기(yaw/pitch 회전 속도). 기존 버튼(달리기·웅크리기·E·사용)은 그대로.
- 머리 흔들림: 걸을 때 살짝, 달릴 때 더. `walkPhase` 를 쓰고, 설정 '화면 흔들림'을 끄면 같이 꺼진다.

### 5.4 월드 짓기 (Level 0)

- 맵 타일에서 메시를 만든다.
  - 바닥: 카펫
  - 천장: 석고 천장 타일 격자
  - 벽: 벽지. 바닥 칸과 닿은 면만 만든다
- 같은 재질은 한 지오메트리로 합쳐서(merge) draw call 을 줄인다.
- 벽 아래쪽엔 걸레받이(얇은 띠)를 둘러 사실감을 더한다.
- 레벨의 다른 사물도 3D 로 놓는다.
  - 열쇠, 바닥 아이템, 사물함(벽에 붙은 철제 캐비닛), 쪽지(바닥의 종이)
  - 출구 문: 잠기면 어둡고, 열리면 위에 EXIT 표지가 빛난다
  - 시체, 조명탄
  - 마닐라 룸 문(0.06% 판에만)
- 위치 데이터는 지금 `level`·`Game` 이 가진 것을 그대로 쓴다.

### 5.5 재질 (절차적 텍스처)

- 캔버스로 256~512px 텍스처를 만든다. 지금 `texture.js` 의 16px 도트 타일은 쓰지 않는다. 색과 무늬 느낌은 참고한다.
  - **벽지**: 누런 바탕에 세로 줄무늬·잔무늬, 얼룩, 아래쪽 습기 자국. 칸마다 조금씩 다르게(시드)
  - **카펫**: 축축한 갈색 계열 잔털 노이즈, 군데군데 짙은 얼룩
  - **천장**: 석고 타일 격자와 구멍 무늬. 형광등 자리는 빛나는 패널
- 노멀맵은 이번 단계에선 넣지 않는다. 품질 '높음'에서만 벽지·카펫에 약한 범프를 넣는다.

### 5.6 조명

진짜 같은 형광등을 수백 개의 실시간 조명으로 켜면 너무 무겁다. 그래서 섞어서 쓴다.

- **구워 둔 밝기**
  - `level.tileLight`(타일별 형광등 밝기, 이미 있음)를 DataTexture(타일당 1픽셀, 부드럽게 보간)로 만든다.
  - 바닥·벽·천장 셰이더에서 곱해서 기본 밝기로 쓴다. 지금 2D 의 어두운 구역(형광등이 나간 곳)도 그대로 어둡게 된다.
- **깜빡임**
  - 깜빡이는 형광등(`level.lights` 의 `flicker`)은 지금 `LightSystem.updateFlicker` 와 같은 타이밍 규칙으로 켜고 끈다.
  - 꺼진 등 주변 타일의 밝기를 DataTexture 에서 그때그때 깎는다.
  - 천장 패널의 발광도 같이 꺼진다.
  - 꺼지고 켜질 때 지금처럼 `flickerSounds` 로 지직 소리를 낸다.
- **가까운 실시간 조명**: 카메라에서 가까운 형광등 몇 개(품질에 따라 4~8개)만 PointLight 로 켜서, 괴물·플레이어·사물에 제대로 빛이 떨어지게 한다.
- **손전등**
  - 내 손전등은 SpotLight 로 카메라에 붙인다. 품질 '높음'에서만 그림자를 켠다.
  - 친구 손전등은 그림자 없는 SpotLight(가까운 몇 명만)와 눈에 보이는 빛줄기(옅은 원뿔 메시)로 보인다.
- **어둠과 안개**: 짙은 FogExp2(누런 회색). '짙은 안개' 모드면 더 짙게. 어두운 곳은 손전등 없이는 거의 안 보인다.
- **정신력 효과**: 정신력이 낮을수록 화면 가장자리가 어두워지고 색이 빠진다. 지금 2D 의 `drawSanityFx`·`drawRainbow` 와 같은 조건이고, 후처리로 낸다.

### 5.7 후처리 (캠코더 느낌)

- EffectComposer 로 다음을 건다: 필름 그레인, 비네트, 약한 색수차, 형광등 블룸, 아주 약한 흐림/번짐.
- 품질별 차이:
  - 낮음: 그레인+비네트만
  - 중간: 블룸 추가
  - 높음: 색수차·그림자 추가
- 지금 2D 의 위험 표시(`danger` 가 높을수록 그레인이 세짐)를 그대로 따른다.

### 5.8 괴물과 사람 모델

모두 three.js 기본 도형(캡슐·박스·실린더)을 이어 붙여 만든다. 걷기는 팔다리를 sin 으로 흔드는 단순한 애니메이션이다.

- **하울러** (Level 0 의 위험한 괴물)
  - 사람보다 큰(약 2.3m) 깡마른 검은 형체, 긴 팔
  - 어둠 속에서도 보이는 빛나는 눈. 기존 `drawMonsterEyes` 처럼 쫓을 때 더 밝다
  - 상태(`m.state`: patrol / chase / search 등)에 따라 걸음 속도와 자세가 바뀐다. 쫓을 땐 앞으로 숙이고 빠르게
  - 하울러의 실제 이동·판정은 서버 그대로다. 클라이언트는 스냅샷 보간 위치(`ClientMonster.interpolate`)에 그린다
- **방랑자(wanderer)**: 해치지 않는 엔티티. 지금 게임에서 방랑자는 플레이어처럼 방호복을 입고 있고, 색은 플레이어 옷 색 중 하나를 빛바래게 쓴다(`sprites.js` `suitPalette`, `GameRoom` 이 무작위 색을 준다). '이름 숨김' 모드(기본 켜짐)와 함께 "저게 내 친구 맞나?" 하는 의심을 만드는 게 핵심이다. 그래서 3D 에서도 **플레이어와 같은 방호복 모델**에 빛바랜 색을 쓰고, 손전등은 없다 (내 판단)
- **다른 플레이어**
  - 몸통·머리·팔다리가 있는 방호복 사람 모델(방랑자와 공유). 옷 색은 지금 고른 색(`SUIT_HEX`)
  - 손전등 빛줄기, 웅크리기 자세, 이름표(5.1 오버레이). '이름 숨김' 모드면 숨긴다
  - 감정 표현 동작(손 흔들기 등)은 이번 단계에선 팔 하나 흔들기 정도로만. 말풍선은 오버레이에 나온다
- **보이는 조건**: 지금 2D 처럼 시야(`hasLOS`)와 밝기로 정한다. 3D 는 벽이 실제로 가려 주므로 따로 숨길 필요가 없다. '보이지 않는 공포' 모드는 4칸 밖 괴물 모델을 숨긴다.
- **잡혔을 때**: 카메라가 괴물 쪽으로 홱 돌고, 그다음 지금의 2D 사망 연출 오버레이(`drawDeathOverlay`)가 나온다. 괴물이 덮치는 점프스케어는 `deaths.js` 사망 연출 안의 lunge 단계에 이미 있다(`renderer.drawJumpscare` 는 호출되지 않는다). 그러니 3D 쪽에서 얼굴을 따로 한 번 더 띄우지 않는다.
- **야간 투시경**: 2D 에서는 시야 범위 안이 벽 너머까지 보인다. 3D 에서는 화면을 초록 단색으로 밝게 하고, 같은 범위 안의 괴물·플레이어를 벽 너머로도 윤곽선(깊이 검사 끈 실루엣)으로 보여 준다. 2D 친구와 같은 방에서 놀 때 공평하게 하기 위해서다 (내 판단).
- **정신력 환각(가짜 스마일러)**: 지금 코드에서 `updateHallucinations` 가 `hallu` 를 늘 비워 두므로(꺼져 있음) 3D 모델을 만들지 않는다.

### 5.9 소리

- 지금 `Sound` 함수들은 볼륨과 좌우(pan)를 받는다. 3D 에서는 pan 을 화면 x 대신 **바라보는 방향 기준** 각도로 계산한다. 엔진에 `panOf(x, y)` 도우미를 하나 두고, 3D 일 때만 yaw 기준으로 바꾼다.
  - 엔티티 이벤트 소리, 발소리, 형광등 지직 소리가 대상이다.
- **보이스챗**: `updateVoice` 의 pan 도 같은 도우미로 바라보는 방향 기준으로 바꾼다. 거리 감쇠·벽 너머 먹먹함은 그대로다.
- **형광등 웅웅 소리(hum)**: 가까운 켜진 형광등이 많을수록 커지게 한다. 지금 `Sound` 에 hum 이 있으면 쓰고, 없으면 추가한다.

### 5.10 화면 위 정보 (HUD)

- 지금 HUD 를 오버레이 캔버스에 그대로 그린다: 미니맵, 미션, 인벤토리, 스태미나·정신력, 메시지, 모드 HUD, 감정 표현 휠.
- 미니맵은 2D 좌표 그대로 쓰고, 내 방향 표시만 yaw 를 따른다. '미니맵 없음' 모드는 그대로 동작한다.
- 화면 가운데에 작은 점(조준점)을 둔다. 바라보는 사물이 상호작용 거리 안이면 "E 숨기" 같은 안내를 그 사물 위에 띄운다. 상호작용 판정 자체(`nearLocker` 등)는 지금 엔진 로직 그대로다.

### 5.11 설정

설정의 '일반' 탭에 세 가지를 추가한다. 영어 번역도 넣는다.
- **3D 화면** (기본 켜짐): 끄면 Level 0 도 2D 로 플레이한다. 저사양 기기용이자, 문제가 생겼을 때 돌아갈 길이다.
- **그래픽 품질**: 낮음 / 중간 / 높음 (기본 중간). 터치 기기(태블릿)는 기본 낮음.
- **마우스 감도**: 슬라이더

설정은 지금처럼 React 쪽에서 저장한다(`components/BackroomsGame.jsx` 의 `loadSettings` / `changeSettings`, 키 `backrooms.settings`). 기본값은 그 컴포넌트와 엔진 `Game.settings` 두 곳에 있으니 둘 다 고친다.

### 5.12 레벨 전환

- `loadRound` 에서 `levelIndex === 0 && settings.threeD !== false` 이면 Renderer3D, 아니면 2D Renderer 를 쓴다.
  - 쓰지 않는 쪽 캔버스는 숨긴다.
  - Renderer3D 는 레벨이 바뀔 때 GPU 자원(지오메트리·텍스처)을 해제한다.
- 3D 에서 2D 로 넘어갈 때 포인터 잠금을 풀고, 이동 방식을 2D 방식(마우스 커서로 조준)으로 되돌린다.

### 5.13 테스트와 확인

- 서버·공용 코드는 바꾸지 않으므로 기존 `npm test` 가 그대로 통과해야 한다.
- 브라우저 없이 돌릴 수 있는 순수 함수에는 단위 테스트를 추가한다(`test/three.mjs`, `npm test` 에 포함).
  - 좌표 변환(px↔m)
  - yaw↔`p.angle` 변환
  - 1인칭 이동 벡터 회전(W 를 누르면 바라보는 방향으로 간다)
  - 바라보는 방향 기준 pan 계산
- 직접 확인할 것 (dev 서버에서)
  - 혼자 하기 Level 0 에서 다음을 모두 해 보고, 열쇠 5개를 모아 탈출해 Level 1(2D)로 넘어가는지 본다: 둘러보기·이동·달리기·웅크리기·손전등·사물함 숨기·아이템 줍기/쓰기
  - 하울러에게 잡혀서 사망 연출이 나오는지 본다
  - 브라우저 두 개로 멀티를 켜서 3D 와 2D(설정에서 끔)가 같은 방에서 서로 보이는지 본다
  - fps 를 확인한다

## 6. 사용자가 정한 것

- 3D 로 만든다. 1인칭이고, 분위기 참고는 친구들끼리 하는 1인칭 백룸 게임 영상이다.
- 가져올 것: 진짜 같은 복도·조명, 친구들과 같이 길 찾는 재미, 쫓길 때의 공포. 스피드런 요소는 제외.
- 첫 버전은 Level 0 하나만 제대로 만든다.
- three.js 로 만든다. 게임 엔진은 나중에 생각한다.
- 작업은 `3d` 브랜치에서 한다.
- 크기: 1m = 32px, 타일 = 1.5m. 서버 속도는 그대로 두고 좁은 복도로 체감 속도를 맞춘다 (빌더 검토 뒤 사용자 선택).
